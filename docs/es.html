HTML a PDF idéntico al navegador, sin navegador en el servidor. El navegador de quien exporta calcula el diseño; PHP solo dibuja el PDF. Funciona en hosting compartido (PHP + GD).

Ver la galería de ejemplosFormato del JSON (format.md)Licencia MIT

Visión general

Generar PDF a partir de HTML suele terminar en uno de estos callejones sin salida:

OpciónProblema
Chrome / Puppeteer en el servidornecesita un VPS o contenedor; no funciona en hosting compartido
wkhtmltopdfbinario en el servidor, CSS antiguo, proyecto descontinuado
Dompdf / mPDF / TCPDF leyendo el HTMLsolo entienden CSS 2.1: sin flexbox, grid, variables, clamp(), filtros… el PDF sale distinto de la pantalla
API externa de PDFcosto, dependencia de terceros y el contenido sale de tu servidor

Jh2Pdf parte de otra idea: el navegador de quien exporta ya es el mejor motor de diseño que existe, y ya está abierto. En lugar de reimplementar CSS en PHP, el navegador calcula dónde va cada palabra, caja, borde e imagen, y PHP solo dibuja esas posiciones. No hay saltos de línea ni cálculo de diseño en el servidor que puedan fallar.

Fiel a la pantallaflexbox, grid, variables CSS, calc(): todo lo que el navegador entiende, porque es él quien mide.
Texto realtexto seleccionable y buscable, con las fuentes incrustadas (subconjunto).
Hosting sencillosolo PHP 8.1 + GD + mbstring. Sin Chrome, sin Node, sin binarios.
Seguro por diseñoel servidor nunca interpreta HTML, CSS ni JS: solo números, colores y texto validados.

Cómo funciona

 NAVEGADOR (js/jh2pdf.js)                               SERVIDOR (PHP)
 ────────────────────────                               ──────────────
 tu HTML + tu CSS                                       Options  (tempDir, fontDir, imageResolver…)
   │ dibuja cada página fuera de la pantalla               │
   │ (espera fuentes e imágenes)                           ▼
   ▼                                                    Layout::clean()   valida todo (el JSON es hostil)
 extractLayout()  recorre el DOM:                          │
   getComputedStyle + Range.getClientRects por palabra     ▼
   │                                                    Renderer::render()  → Dompdf\Cpdf
   ▼                                                       R rectángulo · B bordes · T texto · I imagen
 JSON de operaciones ─────── POST ───────────────────►     M marca a mano · L línea · C/E recorte
 { w, h, pages: [{ bg, ops: [...] }] }                     │
                                                           ▼
                                                        bytes del PDF
  1. Medición (navegador). Cada página se inserta en un contenedor fuera de la pantalla, dentro de tu propio documento, así que tu CSS se aplica. El módulo espera las fuentes (document.fonts.ready) y las imágenes (hasta 4 s cada una).
  2. Extracción. Para cada elemento visible lee el estilo calculado y las cajas; para cada palabra, la posición y el ancho exactos. El resultado es una lista ordenada de operaciones de dibujo (el orden es el orden de pintado).
  3. Dibujo (servidor). PHP valida el JSON y dibuja las operaciones con el Cpdf de Dompdf, usado solo como "lienzo" de PDF. Cada palabra se coloca en su línea base y su espaciado entre letras se ajusta para tener exactamente el ancho medido.

Instalación

Con Composer

composer require geisonq/jh2pdf

O, desde este repositorio: composer install en la raíz (instala Dompdf en vendor/).

Sin Composer

Copia la carpeta y usa el autoloader incluido. Dompdf sigue siendo necesario y tienes que cargarlo tú:

require '/ruta/jh2pdf/autoload.php';      // clases Jh2Pdf\*
require '/ruta/vendor/autoload.php';      // Dompdf

En el navegador

Copia js/jh2pdf.js a tu sitio. Es un módulo ES sin dependencias (~30 KB, sin minificar).

Inicio rápido

1. Navegador

import { extractLayout } from './jh2pdf.js';

const layout = await extractLayout(
  ['<h1>Hola</h1><p>Primera página</p>', '<p>Segunda página</p>'],  // un fragmento de HTML por página
  { width: 794, height: 1123 }                                       // A4 vertical en px CSS
);
const res = await fetch('/pdf.php', {
  method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(layout),
});
const pdf = await res.blob();                                  // application/pdf
window.open(URL.createObjectURL(pdf));

2. Servidor (pdf.php)

require 'vendor/autoload.php';

$raw    = file_get_contents('php://input', false, null, 0, 5_000_000);   // limita el cuerpo
$layout = json_decode((string)$raw, true);
if (!is_array($layout)) { http_response_code(400); exit; }

$options = new Jh2Pdf\Options('/ruta/con/escritura');
try {
    $pdf = (new Jh2Pdf\Renderer($options))->render($layout, 'Título del documento');
} catch (Jh2Pdf\Exception $e) {
    error_log((string)$e->getPrevious());             // el detalle está en la excepción anterior
    http_response_code(500); exit;
}
header('Content-Type: application/pdf');
echo $pdf;

Ejemplos ejecutables: examples/minimal/ (lo mínimo) y demo/ (galería con tablas, efectos e imágenes).

API JavaScript

extractLayout(pages, options) → Promise<Layout>

pages es un array con una entrada por página: un string de HTML, un objeto { html } o cualquier valor, si pasas wrap.

OpciónTipoPor defectoDescripción
width, heightnúmero (px)—Obligatorios. Tamaño de la página en px CSS. En el PDF se convierte en pt × 0,75 (794×1123 px = A4).
wrap(page, i)función → string<div>…</div>HTML completo de la página, con un único elemento raíz. El background-color de la raíz se convierte en el fondo de la página. Útil para pasar elementos existentes: wrap: (el) => el.outerHTML.
hostCssstring—CSS extra dentro del contenedor de medición (por ejemplo, un reset). Limítalo con [data-jh2pdf-host].
marksbooleanfalseDibuja las marcas a mano (.mk.mk-circle etc.).
skip(el)función → boolean—true para no dibujar un elemento ni su contenido.
acceptImage(src)función → boolean—Filtra los src de imagen que se envían. Quien decide de verdad es el servidor.
sanitize(html)función → string—Sanitizador del HTML de cada página (por ejemplo, DOMPurify). El filtro interno se ejecuta encima. Ver Seguridad.

Devuelve { w, h, pages: [{ bg, ops }] }, listo para JSON.stringify. Lanza Error si falta width o height.

Consejo: como la medición ocurre dentro de tu documento, limita el CSS de la página a una clase (por ejemplo, .page) y no dependas del contenedor que la rodea. El contenedor está en position: fixed, fuera de la pantalla, y hereda del <body>. Declara fuente, color y line-height en la raíz de la página.

Formato del JSON

Es el contrato entre el JS y el PHP. Medidas en px CSS, origen en la esquina superior izquierda, colores #rrggbb, opacidad de 0 a 1. La referencia completa está en docs/format.md (en portugués).

{ "w": 794, "h": 1123,
  "pages": [ { "bg": "#ffffff", "ops": [
      { "t": "R", "x": 0, "y": 0, "w": 794, "h": 300, "c": "#4f46e5", "a": 1, "r": [12,12,0,0] },
      { "t": "T", "x": 60, "y": 80, "w": 92.4, "h": 44, "s": "Lorem", "f": "Jh Display", "g": 700, "z": 40, "c": "#ffffff" }
  ] } ] }

CSS soportado

El diseño en sí (flexbox, grid, posicionamiento, calc(), variables, unidades) siempre está soportado, porque quien lo calcula es el navegador. La tabla de abajo trata de lo que se dibuja.

RecursoEstadoDetalles
Texto: familia, peso 400–700, cursiva, tamaño, color, opacidadSíLos pesos fuera de 400–700 se redondean. Las familias sin cursiva se inclinan 12°, como hace el navegador.
text-transform, letter-spacingSíEl ancho final siempre es el medido por el navegador.
text-decoration (subrayado, tachado)ParcialLa línea se dibuja palabra por palabra (no pasa bajo los espacios). El color y el estilo de la decoración se ignoran.
background-color, border-radius (por esquina)Sí
linear-gradientParcialVertical y horizontal, con varias paradas, dibujado como franjas finas. Los ángulos diagonales se ajustan a la dirección más cercana. Sin radial, repeating ni capas.
Bordes (ancho y color por lado)Parcialdashed, dotted y double salen sólidos. Los bordes muy gruesos y redondeados pueden mostrar uniones finas.
box-shadow sin desenfoque (exterior e interior)SíVarias sombras y spread. Interior: solo desplazamiento, sin spread.
box-shadow con desenfoque, text-shadowNoSe ignoran.
opacitySíMultiplicada por los ancestros.
overflow: hidden con border-radiusSíRecorte redondeado de todo lo que haya dentro.
<img> PNG, JPEG, GIF, WebPSíCon object-fit (cover, contain, none, scale-down) y esquinas redondeadas.
filter en imágenesSígrayscale sepia brightness contrast invert blur saturate hue-rotate opacity drop-shadow (aplicados con GD).
Listas: disc circle square decimal lower/upper-alpha, ::markerSíIncluidos start y value.
::before/::after vacíos (content: '')ParcialCon fondo, borde, esquinas y sombra sólida, cuando son position: absolute o display: block. No funciona con inline-block.
Pseudoelementos con texto, contadores, ::first-letterNoUsa un elemento real (<span>) para números y etiquetas.
background-image: url(), transform, clip-path, maskNo
SVG en línea, <canvas>, <video>, <iframe>NoConvierte el canvas en <img src="data:…"> antes de extraer (la demo lo hace).
Ligaduras tipográficasNoPor ejemplo, => en Fira Code se convierte en dos caracteres.
Enlaces clicables en el PDFNoNo se crea ninguna anotación ni acción (es una decisión de seguridad).

Páginas y tamaños

Cada elemento de pages es una página del PDF, del tamaño width × height. No hay paginación automática: lo que exceda la altura de la página se corta. Divide el contenido en páginas antes de extraer (por ejemplo, una sección por página, o midiendo alturas en el navegador).

Formatopx CSS (width × height)PDF (pt)

A4 horizontal1123 × 794842 × 595
Carta (Letter)816 × 1056612 × 792
Diapositiva 16:91280 × 720960 × 540

El tamaño aceptado va de 200 a 4000 px por lado.

Fuentes

Dompdf no lee woff2 ni fuentes variables. Por eso fonts/ contiene TTF estáticos, uno por peso:

fonts/dm-sans-400.ttf   dm-sans-500.ttf   dm-sans-600.ttf   dm-sans-700.ttf   dm-sans-400-italic.ttf …
      └ familia en minúsculas con guiones  └ peso 400/500/600/700              └ cursiva, si existe
  • El navegador informa la familia (la primera de font-family) y el peso de cada palabra. PHP usa el archivo correspondiente; si no existe, usa la fuente de reserva (DejaVu Sans) y el texto sale con otra fuente.
  • La pantalla debe usar el mismo archivo. Declara un @font-face con el mismo nombre de familia apuntando a los TTF (ver demo/fonts.css). Si el navegador mide con otra fuente, el ancho de las palabras no coincide.
  • Incluidas (12 familias, SIL OFL 1.1): Barlow Condensed, DM Sans, Fira Code, Inter, JetBrains Mono, Montserrat, Nunito, Open Sans y cuatro serif renombradas: Jh Serif (de Lora), Jh Serif Text (de Merriweather), Jh Display (de Playfair Display) y Jh Serif Book (de Source Serif 4). Con cursiva: DM Sans y Jh Serif.

Agregar una fuente

pip install fonttools brotli
python tools/generate-fonts.py --fonts fonts.json --src carpeta-de-fuentes --out fonts

El formato de fonts.json está en la cabecera del script. Python solo se necesita para generar los archivos; el servidor usa los TTF ya listos. Si la fuente ya tiene TTF estáticos, basta con copiarlos con el nombre según el patrón de arriba.

Imágenes

El src de cada imagen viene del navegador y no es confiable. Por defecto solo se acepta data: (nada de disco ni de red). Para servir imágenes de tu sistema, implementa un resolvedor y verifica que ese usuario pueda ver ese archivo:

final class MiResolvedor implements Jh2Pdf\ImageResolver
{
    public function load(string $src): ?string
    {
        // solo tu patrón de URL; nunca concatenes el src en una ruta
        if (!preg_match('~^/uploads/([a-f0-9]{16}\.(png|jpg))$~', $src, $m)) return null;
        $f = '/var/app/uploads/' . $m[1];
        return is_file($f) ? file_get_contents($f) : null;
    }
}
$options->imageResolver = new MiResolvedor();

En el navegador, acceptImage evita enviar lo que el servidor rechazaría. Las imágenes se reducen al tamaño en que se muestran (~150 dpi): sin transparencia pasan a JPEG, con transparencia siguen siendo PNG.

Marcas a mano

Extensión opcional, desactivada por defecto (no es HTML/CSS estándar), para resaltar texto con un trazo "hecho a mano": underline, circle, highlight, box, strike, cross.

<span class="mk mk-circle" style="--mk-color:#e5484d">importante</span>

Con marks: true, el extractor envía la caja y el color del texto marcado; PHP dibuja el SVG de la forma, que está en resources/marks.css (o en tu propio CSS, mediante Options::$marksCss). Sin --mk-color, se usa el color del texto. Los elementos pares usan la 2.ª variante (:nth-of-type(even)), y una marca con display: inline que se parte en varias líneas recibe un dibujo por línea. Sin marks: true, las clases .mk se tratan como cualquier otro elemento. El CSS de pantalla (una máscara en ::after) está en demo/pages.css.

Seguridad

Hay dos fronteras, y en cada una lo que viene del otro lado se trata como hostil.

Servidor: el JSON del navegador

Cualquiera que pueda llamar a tu endpoint puede enviar un JSON hecho a mano. Por diseño, el servidor nunca interpreta HTML, CSS ni JavaScript.

AtaqueDefensa
Inyectar HTML, JS o CSS en el textoEl texto va al PDF como glifos (en hexadecimal) y nunca se interpreta.
Inyectar objetos PDF (/JS, /OpenAction, /URI, /Launch)Texto en hexadecimal, título escapado y ningún objeto de acción o anotación creado. Hay una prueba para esto.
Nombre de fuente con ../, ) o byte nuloReducido a [A-Za-z0-9 -] (60 caracteres) y asignado solo a archivos de fontDir.
Leer archivos locales o hacer peticiones (file://, http://, ../)Las imágenes solo pasan por el ImageResolver. En Dompdf están desactivados isRemoteEnabled, PHP y JS, y hay chroot.
Bomba de imagen (PNG pequeño que declara millones de píxeles)La cabecera se lee antes de decodificar: lado ≤ 20 000 px y ≤ 25 megapíxeles.
Agotar CPU o memoriaLímites de páginas, operaciones, imágenes y recortes anidados (≤ 32), topes para sombras y desenfoques, set_time_limit(180).
Números o tipos absurdos (1e999, NaN, arrays, url(...))Layout::num() limita a un intervalo y Layout::color() solo acepta #rgb/#rrggbb.
Filtración de rutas en mensajes de errorSolo se lanza Jh2Pdf\Exception con un mensaje genérico.
Archivos temporales olvidadosNombres aleatorios, borrados al final de cada PDF y barridos después de 1 hora.
Lo que queda a tu cargo: autenticación, CSRF, límite de peticiones y límite del tamaño del cuerpo de la petición (generar PDF es costoso), además del ImageResolver cuando lee archivos. Mantén Dompdf, PHP y GD actualizados.

Navegador: el HTML de entrada

El HTML de cada página entra en el DOM de quien exporta. Si viene de otra persona, es una entrada hostil (XSS). El módulo primero coloca el HTML en un <template> inerte y elimina script, iframe, object, embed, link, meta, base, atributos on*, srcdoc, URLs javascript: y data: que no sean imagen, y expression(). Esto es un filtro de respaldo: para contenido de terceros, usa un sanitizador de verdad:

extractLayout(pages, { width, height, sanitize: (h) => DOMPurify.sanitize(h) });

<style> y url() en el CSS siguen permitidos. No ejecutan código, pero pueden disparar peticiones (rastreo).

Rendimiento

Medido con la galería de ejemplos (7 páginas A4, ~2400 operaciones, 9 imágenes con filtro) en un PC común con XAMPP y PHP 8.2:

EtapaResultado
JSON enviado~460 KB (casi todo es la imagen data: repetida)
PDF generado~300 KB, fuentes incrustadas como subconjunto
PHP, primera generación~6–9 s (registra las fuentes en la caché de Dompdf)
PHP, generaciones siguientes~2–3 s, dominados por los filtros de imagen en GD
  • Los filtros (blur, drop-shadow) son la parte más costosa. Sin ellos, las páginas de texto y tablas tardan fracciones de segundo.
  • La misma imagen con el mismo filtro y tamaño se procesa una sola vez por PDF (hay caché).
  • Para documentos grandes, envía las imágenes por URL y usa un ImageResolver, en lugar de repetir data: en el JSON.

Solución de problemas

SíntomaCausa probable y solución
Texto con una fuente distinta a la de la pantallaNo existe fonts/<familia>-<peso>.ttf para la primera familia de font-family. Agrega el TTF o usa una de las incluidas.
Palabras apretadas o demasiado espaciadasEl navegador midió con otra fuente (la de reserva o la del sistema). Carga la misma fuente con @font-face.
La imagen no apareceEl src no es data: y no hay ImageResolver, o el resolvedor devolvió null, o la imagen superó los límites.
Contenido cortado al final de la páginaNo hay paginación automática. Divide en más páginas.
Los estilos de tu aplicación se "filtran" a la páginaEl contenedor hereda del <body>. Limita el CSS de la página y define fuente, color y line-height en la raíz.
Dompdf is not installedEjecuta composer install o carga vendor/autoload.php antes.

Error 500 sin detalleEs intencional. Registra $e->getPrevious() en tu log.

Cómo contribuir

  • Pruebas: composer install y composer test. No hay framework de pruebas, solo tests/run.php.
  • Criterio de calidad: quedar igual que la pantalla. Genera el PDF desde el navegador (Imprimir → Guardar como PDF) y con esta biblioteca y compáralos lado a lado, ampliando (por ejemplo, con PyMuPDF: page.get_pixmap(dpi=200)).
  • Nueva operación (por ejemplo, degradado radial): (1) el extractor en js/jh2pdf.js emite la operación; (2) Layout::OPS recibe la letra; (3) Renderer::render recibe el case; (4) documéntala en docs/format.md; (5) pruébala en tests/run.php. Valida cada campo nuevo: es una entrada hostil.
  • Estilo: PHP 8.1 con declare(strict_types=1), sin dependencias aparte de Dompdf. JS sin dependencias, con nombres de nivel superior con el prefijo pl.
  • Las contribuciones se aceptan bajo la misma licencia del proyecto (MIT).
