HTML to PDF that looks exactly like the browser, without a browser on the server. The exporting user's browser computes the layout; PHP only draws the PDF. Runs on shared hosting (PHP + GD).

See the examples galleryJSON format (format.md)MIT license

Overview

Generating PDFs from HTML usually ends up in one of these dead ends:

OptionProblem
Chrome / Puppeteer on the serverneeds a VPS or container; does not run on shared hosting
wkhtmltopdfa binary on the server, outdated CSS, discontinued project
Dompdf / mPDF / TCPDF parsing the HTMLonly understand CSS 2.1: no flexbox, grid, variables, clamp(), filters… the PDF looks different from the screen
External PDF APIcost, third-party dependency, and your content leaves your server

Jh2Pdf starts from a different idea: the exporting user's browser is already the best layout engine there is, and it is already open. Instead of reimplementing CSS in PHP, the browser computes where every word, box, border and image goes, and PHP only draws those positions. There is no line breaking or layout computation on the server to get wrong.

Matches the screenflexbox, grid, CSS variables, calc(): anything the browser understands, because the browser does the measuring.
Real textselectable, searchable text with embedded (subset) fonts.
Simple hostingjust PHP 8.1 + GD + mbstring. No Chrome, no Node, no binaries.
Secure by designthe server never interprets HTML, CSS or JS: only validated numbers, colors and text.

How it works

 BROWSER (js/jh2pdf.js)                                 SERVER (PHP)
 ──────────────────────                                 ────────────
 your HTML + your CSS                                   Options  (tempDir, fontDir, imageResolver…)
   │ renders each page off-screen                          │
   │ (waits for fonts and images)                          ▼
   ▼                                                    Layout::clean()   validates everything (the JSON is hostile)
 extractLayout()  walks the DOM:                           │
   getComputedStyle + Range.getClientRects per word        ▼
   │                                                    Renderer::render()  → Dompdf\Cpdf
   ▼                                                       R rectangle · B borders · T text · I image
 JSON of operations ──────── POST ───────────────────►     M hand mark · L line · C/E clip
 { w, h, pages: [{ bg, ops: [...] }] }                     │
                                                           ▼
                                                        PDF bytes
  1. Measuring (browser). Each page is inserted into an off-screen container inside your own document, so your CSS applies. The module waits for fonts (document.fonts.ready) and images (up to 4 s each).
  2. Extraction. For each visible element it reads the computed style and boxes; for each word, its exact position and width. The result is an ordered list of drawing operations (the order is the paint order).
  3. Drawing (server). PHP validates the JSON and draws the operations with Dompdf's Cpdf, used only as a PDF "canvas". Each word is placed on its baseline and its letter spacing is adjusted so it has exactly the measured width.

Installation

With Composer

composer require geisonq/jh2pdf

Or, from this repository: composer install at the root (installs Dompdf into vendor/).

Without Composer

Copy the folder and use the bundled autoloader. Dompdf is still required and you must load it yourself:

require '/path/jh2pdf/autoload.php';      // Jh2Pdf\* classes
require '/path/vendor/autoload.php';      // Dompdf

In the browser

Copy js/jh2pdf.js to your site. It is an ES module with no dependencies (~30 KB, unminified).

Quick start

1. Browser

import { extractLayout } from './jh2pdf.js';

const layout = await extractLayout(
  ['<h1>Hello</h1><p>First page</p>', '<p>Second page</p>'],  // one HTML fragment per page
  { width: 794, height: 1123 }                                   // A4 portrait in CSS px
);
const res = await fetch('/pdf.php', {
  method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(layout),
});
const pdf = await res.blob();                                  // application/pdf
window.open(URL.createObjectURL(pdf));

2. Server (pdf.php)

require 'vendor/autoload.php';

$raw    = file_get_contents('php://input', false, null, 0, 5_000_000);   // limit the body size
$layout = json_decode((string)$raw, true);
if (!is_array($layout)) { http_response_code(400); exit; }

$options = new Jh2Pdf\Options('/writable/path');
try {
    $pdf = (new Jh2Pdf\Renderer($options))->render($layout, 'Document title');
} catch (Jh2Pdf\Exception $e) {
    error_log((string)$e->getPrevious());             // details are in the previous exception
    http_response_code(500); exit;
}
header('Content-Type: application/pdf');
echo $pdf;

Runnable examples: examples/minimal/ (the bare minimum) and demo/ (gallery with tables, effects and images).

JavaScript API

extractLayout(pages, options) → Promise<Layout>

pages is an array with one entry per page: an HTML string, a { html } object, or any value if you pass wrap.

OptionTypeDefaultDescription
width, heightnumber (px)—Required. Page size in CSS px. In the PDF it becomes pt × 0.75 (794×1123 px = A4).
wrap(page, i)function → string<div>…</div>The complete HTML of the page, with a single root element. The root's background-color becomes the page background. Handy for passing existing elements: wrap: (el) => el.outerHTML.
hostCssstring—Extra CSS inside the measuring container (for example, a reset). Scope it with [data-jh2pdf-host].
marksbooleanfalseDraws hand-drawn marks (.mk.mk-circle etc.).
skip(el)function → boolean—Return true to not draw an element and its contents.
acceptImage(src)function → boolean—Filters the image src values that are sent. The server makes the real decision.
sanitize(html)function → string—Sanitizer for each page's HTML (for example, DOMPurify). The built-in filter still runs on top. See Security.

Returns { w, h, pages: [{ bg, ops }] }, ready for JSON.stringify. Throws Error if width or height is missing.

Tip: since measuring happens inside your document, scope the page CSS under a class (for example, .page) and don't depend on the surrounding container. The container is position: fixed, off-screen, and inherits from <body>. Declare font, color and line-height on the page root.

JSON format

This is the contract between the JS and PHP sides. Measurements in CSS px, origin at the top-left corner, colors as #rrggbb, opacity from 0 to 1. The full reference is in docs/format.md (in Portuguese).

{ "w": 794, "h": 1123,
  "pages": [ { "bg": "#ffffff", "ops": [
      { "t": "R", "x": 0, "y": 0, "w": 794, "h": 300, "c": "#4f46e5", "a": 1, "r": [12,12,0,0] },
      { "t": "T", "x": 60, "y": 80, "w": 92.4, "h": 44, "s": "Lorem", "f": "Jh Display", "g": 700, "z": 40, "c": "#ffffff" }
  ] } ] }
OpNameMain fields
Rfilled rectanglex y w h c a r[4]
Bbordersx y w h s[4]=[width,color,a] (top, right, bottom, left) r[4]
Ttext (one word)x y w h s f g i z c a l d (d: 1 underline, 2 line-through)
Iimagex y w h u k[4] f a r[4] (u = src, k = clip box, f = CSS filter)

Llinex y x2 y2 c w a

Supported CSS

Layout itself (flexbox, grid, positioning, calc(), variables, units) is always supported, because the browser computes it. The table below is about what gets drawn.

FeatureStatusDetails
Text: family, weight 400–700, italic, size, color, opacityYesWeights outside 400–700 are rounded. Families without italic are slanted 12°, as the browser does.
text-transform, letter-spacingYesThe final width is always the one measured by the browser.
text-decoration (underline, line-through)PartialThe line is drawn word by word (it does not run under spaces). Decoration color and style are ignored.
background-color, border-radius (per corner)Yes
linear-gradientPartialVertical and horizontal, multiple stops, drawn as thin bands. Diagonal angles snap to the nearest direction. No radial, repeating or layered gradients.
Borders (width and color per side)Partialdashed, dotted and double render as solid. Very thick rounded borders may show thin seams.
box-shadow without blur (outer and inset)YesMultiple shadows and spread. Inset: offset only, no spread.
Blurred box-shadow, text-shadowNoIgnored.
opacityYesMultiplied through ancestors.
overflow: hidden with border-radiusYesRounded clipping of everything inside.
<img> PNG, JPEG, GIF, WebPYesWith object-fit (cover, contain, none, scale-down) and rounded corners.

Lists: disc circle square decimal lower/upper-alpha, ::markerYesIncluding start and value.
Empty ::before/::after (content: '')PartialWith background, border, corners and solid shadow, when position: absolute or display: block. Does not work with inline-block.
Pseudo-elements with text, counters, ::first-letterNoUse a real element (<span>) for numbers and labels.
background-image: url(), transform, clip-path, maskNo
Inline SVG, <canvas>, <video>, <iframe>NoConvert a canvas to <img src="data:…"> before extracting (the demo does this).

Pages and sizes

Each item in pages is one PDF page, sized width × height. There is no automatic pagination: anything taller than the page is cut off. Split your content into pages before extracting (for example, one section per page, or by measuring heights in the browser).

FormatCSS px (width × height)PDF (pt)
A4 portrait794 × 1123595 × 842
A4 landscape1123 × 794842 × 595
US Letter816 × 1056612 × 792
16:9 slide1280 × 720960 × 540

Accepted sizes range from 200 to 4000 px per side.

Fonts

Dompdf cannot read woff2 or variable fonts. That is why fonts/ holds static TTFs, one per weight:

fonts/dm-sans-400.ttf   dm-sans-500.ttf   dm-sans-600.ttf   dm-sans-700.ttf   dm-sans-400-italic.ttf …
      └ lowercase hyphenated family        └ weight 400/500/600/700            └ italic, if available
  • The browser reports the family (the first one in font-family) and the weight of each word. PHP uses the matching file; if it does not exist, it falls back to DejaVu Sans and the text comes out in a different font.
  • The screen must use the same file. Declare an @font-face with the same family name pointing to the TTFs (see demo/fonts.css). If the browser measures with a different font, the word widths won't match.
  • Bundled (12 families, SIL OFL 1.1): Barlow Condensed, DM Sans, Fira Code, Inter, JetBrains Mono, Montserrat, Nunito, Open Sans, and four renamed serif families: Jh Serif (from Lora), Jh Serif Text (from Merriweather), Jh Display (from Playfair Display) and Jh Serif Book (from Source Serif 4). With italics: DM Sans and Jh Serif.

Adding a font

pip install fonttools brotli
python tools/generate-fonts.py --fonts fonts.json --src font-source-folder --out fonts

The fonts.json format is described in the script header. Python is only needed to generate the files; the server uses the ready-made TTFs. If the font already ships static TTFs, just copy them using the naming pattern above.

Images

Each image's src comes from the browser and is not trusted. By default only data: is accepted (no disk, no network). To serve images from your system, implement a resolver and check that this user may see this file:

final class MyResolver implements Jh2Pdf\ImageResolver
{
    public function load(string $src): ?string
    {
        // only your URL pattern; never concatenate src into a path
        if (!preg_match('~^/uploads/([a-f0-9]{16}\.(png|jpg))$~', $src, $m)) return null;
        $f = '/var/app/uploads/' . $m[1];
        return is_file($f) ? file_get_contents($f) : null;
    }
}
$options->imageResolver = new MyResolver();

In the browser, acceptImage avoids sending what the server would refuse. Images are downsized to their displayed size (~150 dpi): opaque ones become JPEG, transparent ones stay PNG.

Hand-drawn marks

An optional extension, off by default (it is not standard HTML/CSS), for highlighting text with a "hand-drawn" stroke: underline, circle, highlight, box, strike, cross.

<span class="mk mk-circle" style="--mk-color:#e5484d">important</span>

With marks: true, the extractor sends the box and color of the marked text; PHP draws the shape's SVG from resources/marks.css (or your own CSS, via Options::$marksCss). Without --mk-color, the text color is used. Even elements use the 2nd variant (:nth-of-type(even)), and a mark with display: inline that wraps gets one drawing per line. Without marks: true, .mk classes are treated like any other element. The on-screen CSS (a mask on ::after) is in demo/pages.css.

Security

There are two trust boundaries, and on each one whatever comes from the other side is treated as hostile.

Server: the JSON from the browser

Anyone who can call your endpoint can send hand-crafted JSON. By design, the server never interprets HTML, CSS or JavaScript.

AttackDefense
Injecting HTML, JS or CSS into textText goes into the PDF as glyphs (hex-encoded) and is never interpreted.
Injecting PDF objects (/JS, /OpenAction, /URI, /Launch)Hex-encoded text, escaped title, and no action or annotation objects are created. There is a test for this.
Font name with ../, ) or a null byteReduced to [A-Za-z0-9 -] (60 characters) and mapped only to files in fontDir.
Reading local files or making requests (file://, http://, ../)Images only go through the ImageResolver. Dompdf runs with isRemoteEnabled, PHP and JS disabled, plus a chroot.
Image bomb (a tiny PNG declaring millions of pixels)The header is read before decoding: side ≤ 20,000 px and ≤ 25 megapixels.
Exhausting CPU or memoryLimits on pages, operations, images and nested clips (≤ 32), caps on shadows and blurs, set_time_limit(180).
Absurd numbers or types (1e999, NaN, arrays, url(...))Layout::num() clamps to a range and Layout::color() only accepts #rgb/#rrggbb.
Leaking paths in error messagesOnly Jh2Pdf\Exception with a generic message is thrown.
Leftover temporary filesRandom names, deleted at the end of each PDF and swept after 1 hour.
Your responsibility: authentication, CSRF, rate limiting and a request body size limit (rendering PDFs is expensive), plus the ImageResolver when it reads files. Keep Dompdf, PHP and GD up to date.

Browser: the input HTML

Each page's HTML goes into the exporting user's DOM. If it comes from someone else, it is hostile input (XSS). The module first places the HTML in an inert <template> and removes script, iframe, object, embed, link, meta, base, on* attributes, srcdoc, javascript: URLs and non-image data: URLs, and expression(). This is a fallback filter: for third-party content, use a real sanitizer:

extractLayout(pages, { width, height, sanitize: (h) => DOMPurify.sanitize(h) });

<style> and url() in CSS are still allowed. They don't execute code, but they can trigger requests (tracking).

Performance

Measured with the examples gallery (7 A4 pages, ~2,400 operations, 9 filtered images) on an ordinary PC with XAMPP and PHP 8.2:

StageResult
JSON sent~460 KB (mostly the repeated data: image)
Generated PDF~300 KB, fonts embedded as subsets
PHP, first run~6–9 s (registers fonts in the Dompdf cache)
PHP, later runs~2–3 s, dominated by image filters in GD
  • Filters (blur, drop-shadow) are the most expensive part. Without them, text and table pages take a fraction of a second.
  • The same image with the same filter and size is processed only once per PDF (cached).
  • For large documents, send images by URL and use an ImageResolver instead of repeating data: in the JSON.

Troubleshooting

SymptomLikely cause and fix
Text in a different font than on screenThere is no fonts/<family>-<weight>.ttf for the first family in font-family. Add the TTF or use a bundled one.
Words squeezed or spaced outThe browser measured with another font (the fallback or a system font). Load the same font with @font-face.
Image does not appearThe src is not data: and there is no ImageResolver, or the resolver returned null, or the image exceeded the limits.
Content cut off at the bottom of the pageThere is no automatic pagination. Split into more pages.
Your app's styles "leak" into the pageThe container inherits from <body>. Scope the page CSS and set font, color and line-height on the root.
Dompdf is not installedRun composer install or load vendor/autoload.php first.
Options::$tempDir must be an existing writable directoryCreate the directory and give the PHP user write permission.
Error 500 with no detailsThat's intentional. Log $e->getPrevious().

LGPL in practice: Dompdf is used as an unmodified library installed by Composer. That is compatible with Jh2Pdf's MIT license and with use in closed-source software. The LGPL only requires that, if you modify Dompdf itself and distribute it, you publish those changes, and that users can swap the Dompdf version (which Composer already allows).
Reserved Font Names (RFN): Lora, Merriweather, Playfair Display and Source Serif 4 (reserved name "Source") have a Reserved Font Name. Our static instances are modified versions (generated from the variable fonts), and the OFL forbids modified versions from using the reserved name. That is why they ship renamed as Jh Serif, Jh Serif Text, Jh Display and Jh Serif Book, with the original copyright notices kept in fonts/OFL.txt. If you generate new instances of an RFN font, rename them as well.

Contributing

  • Tests: composer install and composer test. There is no test framework, just tests/run.php.
  • Quality bar: match the screen. Produce a PDF from the browser (Print → Save as PDF) and from this library and compare them side by side, zoomed in (for example, with PyMuPDF: page.get_pixmap(dpi=200)).
  • New operation (for example, radial gradients): (1) the extractor in js/jh2pdf.js emits the operation; (2) Layout::OPS gets the letter; (3) Renderer::render gets the case; (4) document it in docs/format.md; (5) test it in tests/run.php. Validate every new field: it is hostile input.
  • Style: PHP 8.1 with declare(strict_types=1), no dependencies besides Dompdf. Dependency-free JS, with top-level names prefixed with pl.
  • Contributions are accepted under the project's license (MIT).
